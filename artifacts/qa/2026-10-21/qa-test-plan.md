# Independent QA test plan — KidsJellyFin clients

Prepared 21 October 2026 before client execution. Owner: QA Specialist.

## Basis and verdict rules

The two version1.0 functional specs are the sole requirement basis. Installed apps are tested as found: no source edits, builds, installs, fixtures, backend changes, authority extensions or fixes. All143 requirement IDs map exactly once below. Each case is PASS only if every listed requirement is demonstrated in full by current runtime evidence. Otherwise it is FAIL, classified as observed mismatch or unable to verify; partial observations never become a whole-case PASS. Historical results and source inspection are not runtime passes. Optional notification absence alone is not a required-feature defect.

Read-only UI and existing-account unlock are permitted. Preserve media, libraries, existing jobs/history/revisions, tokens and all settings. Stop blocked live-control/media cases if fresh legitimate scope is absent. One read-only service blocker can support several affected case failures; do not repeat it per requirement. No destructive sign-out/reset/account replacement or real approval writes are performed merely to manufacture coverage. Reboot the iOS simulator between each phone automation case; do not erase it. No debugger suspension or physical-device actions.

## Execution and evidence

Capture installed bundle/build hashes once, sanitized UI label/frame snapshots and screenshots where useful. Never save credentials, raw private logs, tokens or private device IDs in report evidence. Record expected versus actual, evidence reference, and inability reason per case. Active safe exploration: CQA-04,05,07,13,14 and PQA-01,03,06,09,11,12(readonly),13–19(readonly),21,24. Other cases require conditions not assumed available; document blockers and partial observations without mutation. Plan cases may share a read-only observation but full verdict criteria remain strict.
